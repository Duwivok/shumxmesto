# SHUM Mini App

Мобильный лендинг Telegram Mini App с анонимным RSVP. Интерфейс остаётся
статическим, а `POST /api/rsvp` выполняется на том же домене Node.js-сервисом.
Финальное размещение рассчитано на VPS Timeweb Cloud в российской локации, не на
GitHub Pages.

## RSVP

При нажатии на сигарету приложение одновременно запускает существующую анимацию
и подтверждает RSVP. Канал открывается только после успешного ответа API и
окончания анимации. Повторное нажатие снова открывает канал, но не отправляет
новый запрос, если в локальном хранилище уже есть состояние `confirmed`.

Клиент хранит под ключом `shum:rsvp:2026-09-19:v1` только:

```json
{
  "version": 1,
  "status": "pending или confirmed",
  "voteId": "случайный UUID v4"
}
```

После сетевой ошибки остаётся `pending`, поэтому следующий тап отправляет тот же
`voteId`. Если `localStorage` запрещён, состояние сохраняется только в памяти до
перезагрузки страницы. Cookies не используются.

Сервер принимает строго JSON `{ "voteId": "UUID v4" }`. SQLite-транзакция и
уникальный ключ обеспечивают атомарный учёт одного `voteId`. В базе находятся
только общий счётчик, случайные идентификаторы попыток и технический флаг того,
что уведомление было зарезервировано для отправки. Даты голосов не сохраняются.

## Обязательная настройка

1. В [site/rsvp-config.js](site/rsvp-config.js) заполнить `channelUrl` точной
   ссылкой `https://t.me/...` без UTM-меток и других параметров.
2. Если это другое мероприятие, одновременно поменять `storageKey`. Новый ключ
   означает новое локальное RSVP-состояние.
3. На сервере создать `/etc/shum.env` по примеру [.env.example](.env.example):

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
PUBLIC_ORIGIN=https://YOUR_DOMAIN
RSVP_DB_PATH=/var/lib/shum/rsvp.sqlite
RSVP_OPEN=true
RSVP_GLOBAL_LIMIT_PER_MINUTE=300
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ORGANIZER_CHAT_ID=...
```

`TELEGRAM_ORGANIZER_CHAT_ID` — чат организатора или специальная группа события,
не идентификатор посетителя. Файл `/etc/shum.env` должен читаться только root и
пользователем сервиса. Секреты нельзя помещать в `site/`, Git или Nginx-конфиг.

## Проверка

Нужен Node.js 22.13 или новее; внешних npm-пакетов нет.

```powershell
cmd /c npm test
```

Тесты используют поддельный Telegram notifier и не отправляют настоящих
сообщений. Обычный `npm start` использует реальные переменные окружения и при
реальном RSVP вызовет Telegram Bot API.

## Развёртывание на Timeweb

1. Выбрать сервер и резервные копии в российской локации. Не подключать внешний
   CDN или прокси без отдельной проверки его географии и журналов.
2. Установить Node.js 22.13+, Nginx и TLS-сертификат; разместить проект в
   `/opt/shum`, а каталог БД создать как `/var/lib/shum` с владельцем `shum`.
3. Установить [deploy/timeweb/shum.service.example](deploy/timeweb/shum.service.example)
   как `/etc/systemd/system/shum.service`, заполнить `/etc/shum.env`, затем
   включить сервис.
4. Адаптировать [deploy/timeweb/nginx.conf.example](deploy/timeweb/nginx.conf.example),
   заменить `YOUR_DOMAIN`, проверить сертификаты и включить конфигурацию.
5. Проверить `https://YOUR_DOMAIN/`, затем обновить URL Mini App в BotFather.
6. После переключения отключить/снять с публикации старый GitHub Pages в
   настройках репозитория: удаление workflow не удаляет уже опубликованный
   Pages-артефакт автоматически.

Nginx раздаёт `site/` сам, а в Node проксирует только `/api/rsvp`. В примере
отключены access/error request logs, очищаются `Cookie`, `Referer`, `User-Agent`,
`X-Forwarded-For` и `X-Real-IP`. `Origin` сохраняется только для проверки
same-origin. Сам Nginx и сеть Timeweb всё равно технически получают IP и
заголовки до их удаления.

GitHub Pages публикует только визуальный preview. На hostname
`duwivok.github.io` RSVP принудительно отключён: нажатие проигрывает анимацию,
но не обращается к хранилищу, API и Telegram. Серверный RSVP предназначен только
для будущего домена Timeweb. Скрипт `deploy.ps1` отправляет исходники в Git и
обновляет preview, но не разворачивает Node.js-сервис на Timeweb.

## Уведомление Telegram

Этот же бот принимает от чата организатора команды `/hide` и `/show`. Они
глобально переключают закрытую и открытую версии раздела «Гео». Состояние и
позиция чтения Telegram updates сохраняются в той же SQLite-базе; команды из
других чатов игнорируются. Открытый раздел обновляет состояние раз в 10 секунд.

Для нового `voteId` сервер сначала атомарно фиксирует голос, затем необратимо
резервирует одно уведомление и отправляет организатору только `+1`. Повторный
API-запрос не увеличивает счётчик и не отправляет сообщение.

Транзакция между SQLite и внешним Telegram Bot API невозможна. Выбрана стратегия
at-most-once: она исключает автоматический дубль уведомления, но при падении
процесса между резервированием и отправкой либо при неопределённой сетевой ошибке
одно сообщение может не прийти. Сам счётчик при этом остаётся корректным.

## Закрытие события и удаление UUID

После мероприятия:

1. установить `RSVP_OPEN=false` и перезапустить сервис;
2. сделать резервную копию агрегированного итога при необходимости;
3. запустить `npm run finalize-event` с окружением сервиса и дополнительной
   переменной `CONFIRM_FINALIZE=YES`;
4. не открывать RSVP снова с очищенной таблицей для того же события.

Команда удаляет все случайные `voteId`, сохраняя агрегированный итог. Она
намеренно не запускается без обоих подтверждений.

## Минимизация данных и ограничения

Приложение не подключает Telegram Web App SDK, не читает и не отправляет
Telegram ID, `initData`, имя, username, телефон или фотографию. Для учёта не
используются IP, User-Agent, Referer, fingerprint или cookies. Клиентский запрос
содержит только случайный идентификатор попытки.

Ограничения приняты сознательно:

- очистка хранилища, другое устройство или новый UUID позволяют ещё один `+1`;
- глобальный лимит запросов не использует IP, поэтому при атаке может временно
  затронуть всех посетителей и не защищает от медленного накручивания;
- Telegram, Timeweb, DNS/DDoS-инфраструктура, ОС и сетевое оборудование могут
  обрабатывать технические данные независимо от прикладного кода;
- настройки журналирования, снапшотов, поддержки, DDoS/CDN и сроки хранения у
  провайдера нельзя подтвердить из репозитория;
- резервные копии и снапшоты могут сохранять удалённые `voteId` дольше основной
  базы, поэтому для них нужен отдельный срок удаления;
- архитектура минимизирует данные, но сама по себе не является гарантией полного
  соответствия 152-ФЗ. Нужны проверка Timeweb, организационные документы и
  юридическая оценка обязанностей владельца, включая уведомление Роскомнадзора.
